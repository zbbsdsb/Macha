# 路径一：SepMay / IVY 生命周期（IC）

> **STATUS: PENDING — 头脑风暴冻结件。** 已定项可直接引用；未定项见 §5，**不阻塞任何实现**。
> 原案：9.5；本轮收敛：2026-09-14。
> 层级：**Macha Core 侧（Phase 3）的候选路线**——不是 Layer 的事，本文件不改任何代码。
> 原则：**一切即插件**。

## 1. 主张（一句话）

NPC 不该为每一次交互都付整条思维链的代价：交互被组织进有明确生死的**生命周期单元**，
单元内只在局部上下文里算，**关闭时**把结果回流到内部信息源。

## 2. 结构（原案）

```text
接收域                    运算域                     输出域
外部信息源 ┐                                    ┌ Ive Chunk → Ive Thread …
           ├→ 算子集合（一切即插件）→ ───────────┤ Ive Chunk → Ive Thread …
内部信息源 ┘                                    └
     ↑                                              │
     └──────────── 数据回流 ←────────────────────────┘
```

原案自标的核心难点：**生命周期与计算节奏**。

> **图的读法（2026-09-15 补充）**
> 1. **回流不改写外部信息源**：被改写的只有"他自己"。事实 append-only，内部状态才可提交更新。
> 2. 内部信息源同时是运算域的**输入**与回流的**目标**，因此图上有一个环
>    `输出域 → 内部信息源 → 运算域`；这个环必须由 IC 的**关闭时点（两阶段提交）**做闸门，
>    否则运算域会读到自己未提交的中间态。
> 3. 因此接收域的职责是**准入（admission）**，不是"接收"：决定什么进入这个 agent 的世界模型、
>    以什么粒度、带什么不确定性（`window` / `truncated` / `verifiability`）。**接收域不做赋义**——
>    赋义属运算域的算子。
> 4. 正式映射表与四条判定问题见 [`../../../docs/architecture.md`](../../../docs/architecture.md) §1.5。

## 3. 层级定位（本轮最重要的收敛）

三层，互不越界：

| 层 | 管什么 |
|---|---|
| 认知层 | NPC 怎么想、记什么、有无人格、一致不一致 |
| **数据组织层 = IC（Chunk / Thread）** | **谁和谁归一组、这组数据活多久、以什么粒度被写出与读入** |
| 环境层（Layer） | Minecraft 发生了什么 |

**单向约束**：IC 不决定 NPC 怎么想；**但 IC 决定 NPC 能想起什么粒度**。
IC 因此只有一条设计义务——

> **不得产生"人不可能有的记忆形态"**（精确复述三小时前每一句；同一件事存在两套互不知情的记忆）。

这条把"忘 vs 记得太具体"从人格问题降级为**数据层约束**：测试里出现"记得比人多"或"两套记忆互不知道"，
一律算 IC 的 bug，与人格设定无关。

## 4. 已定 / 基线（可直接作为实现依据）

| 条目 | 状态 | 来源 |
|---|---|---|
| Ive Chunk = 管理**一组具有相同特性的 Thread** 的容器 | 已定 | 用户 |
| Thread **不跨 Chunk** | 已定 | 用户 |
| Chunk **不嵌套**（只一层） | 已定 | 用户 |
| Chunk **关闭时**数据回流 | 已定 | 用户 |
| 回流分三路：**事实件 / 陈述件（他自己的版本）/ 权重** | 基线 | 本轮（未被反对） |
| **两阶段**：Chunk 内只写暂存，关闭时一次性提交 | 基线 | 本轮 |
| **中断 ≠ 关闭**：中断只提交事实件，不产生"他的版本" | 基线 | 本轮 |
| 回流目标是**单一内部信息源**；多视角是**读法**不是**写法** | 基线 | 本轮 |
| IC 不判断重要性、不定义人格、不解释情境 | 已定 | 用户（"Chunk 是数据层的组织形式"） |
| 深度差异由**情境**决定 | 已定 | 用户 |
| 深度差异可被感知，但必须**归因于角色状态**，不得在同一节拍内翻转 | 已定（本轮裁决） | Q8 |
| 特性集候选：**参与者集 / 活动类 / 寿命类 / 资源类**（须正交、宜少） | 基线 | 本轮 |

> 注：**重要性、情绪、关系亲密度、戏剧价值**明确**不许**进特性集——它们需要判断，属认知层输出；
> 认知层可以贴标签，但调度侧不得自行计算。

## 7. 对现有工作的影响

**映射已定（2026-09-15）**：Layer ↔ 接收域 ↔ plugin 的正式映射表与四条判定问题写在
[`../../../docs/architecture.md`](../../../docs/architecture.md) §1.5。要点：

- Layer 是**外部信息源的生产者**，不在接收域内，也读写不了内部信息源；
- 意图流（`ActionCall`）**不经过接收域**，只有事实回流经过；
- **plugin 不是 Layer**，它是该 Layer 在一个环境内的**部署载体** → 不持跨会话状态、重启不丢记忆、
  不含任何"需要历史"的逻辑。

**仍然只是预留**（不实现、不冻结）：IC 预期会让协议多一些东西，待试跑实测后在
[`../../plans/minecraft-layer/01-protocol-v0.md`](../../plans/minecraft-layer/01-protocol-v0.md) §9 登记：

- `action_result(pending)` 语义（"已接受、稍后完成"）；
- observation 的**节奏/压力事实**（玩家等待时长、是否处于战斗——是事实，不是解释）；
- action 的 **deadline / budget**。

## 8. 解冻后的最小可证伪版本（先放着）

一个 NPC、两条交互流（一紧一深）、一个 Chunk = { 开启触发器 · 预算档 · 局部工作集 · 关闭触发器 · 回流记录 }。

判据三条：① 同等可感知质量下，峰值延迟显著下降；② 脚本化测试里**零条"人不会有的记忆"**；
③ 深度档随机切换，评审**分辨不出**。（②③ 分别对应 §3 的唯一义务与论文的 matched-surface 主张。）

## 9. 反对意见（留给未来的自己）

- 若 IC 最终只是"分批写内存"，那它就是普通的内存分层，**不值得叫一条路径**。
- 真正的风险不在 Chunk 怎么划，而在**回流那一步**：它是人格漂移与假记忆的唯一产地。
  若 §4 的三路分离挡不住它，IC 应被**整条放弃**，而不是继续加机制。
