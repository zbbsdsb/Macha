## 三条硬规矩

1. **未定项不阻塞**：任何一条未定，都不构成"不能推进 Layer"的理由。
2. **不猜**：未定项如果要被"临时猜一个"，必须显式标注为临时假设，并写明作废条件。
3. **到点必须回答**：每条下面都写了"何时必须回答"；到点仍未回答，则该路径**不得解冻**。

## D1 · 寿命类怎么分档 ★ 最高优先

- **问题**：Chunk 的"寿命类"按什么切分？（一次相遇 / 一天 / 一段关系 / 别的切法。）
- **为什么卡**：它是 Chunk **关闭时机**的唯一依据。不定它，"关闭时回流"无从发生。
- **现状倾向**：未定。倾向按"叙事可辨的边界"切（玩家能感到的段落），而不是按挂钟时间。
- **何时必须回答**：**路径解冻前**（否则解冻出来的东西无法关闭）。
- **谁来答**：用户（这是设计判断，不是实现选择）。

## D2 · 分组标准由谁声明、怎么声明

- **问题**：特性集（参与者集/活动类/寿命类/资源类）由谁定义？Thread 的标签由谁贴？
- **现状倾向**：作者定义**闭合枚举**；标签由创建 Thread 的一方贴；**无标签不猜**——落到默认 Chunk
  并报一条可见的错，由作者决定是否新增枚举值。
- **判据（用来定夺）**：**出错时该谁付费。** 推断式分组出错 → 玩家付费；声明式出错 → 设计者付费。
  数据层应让设计者付费。
- **何时必须回答**：路径解冻时（与 D1 同时）。
- **谁来答**：用户 + 实现方共同（枚举内容偏设计，报错行为偏实现）。

## D3 · "语义调度器"是否成立

- **问题**：Chunk 由"专门的语义调度器"划定（原案自标存疑）。
- **本轮立场**：**反对**把"语义"放进调度器。它一旦需要理解情境，就成了第四个认知体——
  谁授权它解释世界？必然晚一步；而且无法测试。主张**声明式匹配 + 装箱**。
- **反驳条件（能推翻我）**：举出一个真实场景，其中"这两条 Thread 该归为一组"**无法**用声明的标签
  表达、必须靠运行期语义推断。举得出来，则调度器确实需要语义。
- **何时必须回答**：路径解冻前。
- **谁来答**：用户（举证或采纳立场）。

## D4 · 权重更新的语义 ★ 风险最高

- **问题**：回流三路里的"权重"，是**数值自适应**，还是**写一条可读结论**？
- **为什么重要**：这是**人格漂移与假记忆的唯一产地**——整条路径的生死线。
- **现状倾向**：未定。技术上是"有界、可回放、可撤回"的约束先于表示形式。
- **何时必须回答**：**最早也要在写最小可证伪版本之前**；若届时无法给出"漂移可被检出"的判据，
  按路径 §9 的反对意见处理——**整条放弃**，而不是继续加机制。
- **谁来答**：用户 + 实现方。

## D7 · 接收域"准入（admission）"组件的名字与最小契约 ★ 新增

- **问题**：Layer 侧有 `EnvironmentPort` 作为边界契约；Core 侧的**准入**这一步（接收 → 去重/排序 →
  标 provenance 与不确定性 → 落外部信息源）**没有名字，也没有契约**。
- **为什么重要**：它是"事实进入这个 agent 的世界模型"的**唯一闸门**；没有它，`window` /
  `truncated` / `verifiability` 无处落地，"有门的事实"就退化成"世界的拷贝"。
- **现状倾向**：暂名 `Intake`；成员至少含 `admit(observation|event) → 外部信息源条目`。
- **边界**：**只准入事实，不做赋义**（赋义属运算域算子）。
- **何时必须回答**：写 Macha Core（Phase 3）之前；不阻塞当前 Layer 工作。
- **谁来答**：用户 + Core 设计方。
