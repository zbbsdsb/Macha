# Paths（并行路径）

为什么有这个目录：Macha 的开发难度极高，**单一路线风险不可接受**。所以我们并行持有若干"路径"，
每条独立成文、各自标清**已定 / 未定 / 评估 / 放弃条件**，而不是把所有想法揉进一份总设计里。

## 目录结构（每个路径一个文件夹）

```text
research/paths/
├── README.md                    # 本文件：目录约定 + 索引
└── NN-<name>/                   # 一条路径 = 一个文件夹
    ├── README.md                #   路径本体：主张 · 结构 · 层级定位 · 已定 · 未定 · 冻结/解冻条件 · 反对意见
    ├── open-decisions.md        #   未定决策：每条写清"何时必须回答"与"谁来答"
    └── eval/                    #   评估：评分与研究者的判断（**每条路径必须有**）
        └── YYYY-MM-DD-evaluation.md
```

## 约定

- **生成方法**：[`00-brainstorm-heuristics.md`](00-brainstorm-heuristics.md)（H1–H6，适用于整个 Macha）。
- 命名：路径目录用 `NN-<name>`（NN 为两位序号）。
- 路径本体（`README.md`）至少包含：**主张 · 结构 · 层级定位 · 已定 · 未定摘要 · 冻结或解冻条件 ·
  与其他路径的关系 · 反对意见**。
- **每条路径必须有 `eval/`**：至少一份评估记录，写清打分维度、最强项、最弱项、涨分条件、
  以及"什么会让它降级/被放弃"。评估是**外部判断**，不是团队结论。
- **未定项不阻塞**：未定项放 `open-decisions.md`，并标明"何时必须回答"；到点未答则该路径不得解冻。
- **现实检验优先于推演**：一条路径被现实否掉就**整条归档**，不做局部缝补。
- 路径之间**不合并**，除非有实测证据说明它们其实是同一件事。
