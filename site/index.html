一 · 我们想要的游戏智能体

玩家要的不是能力，是世界的回应

玩家想要的不是一堆能力，而是世界的回应。我们把提问方式从「智能体应该具备什么能力」换成「玩家希望这个世界如何对待他」，并把答案定义为：一个被世界规则约束、拥有自己的边界、能让玩家的行为留下可理解后果的他者。智能体只是世界变得「有回应」的那个界面。

随着 NPC 行为进入开放式，玩家感知到的关系由一组当前架构既不计算也不保证的结构条件决定，而模型能力不是它的主要变量。玩家对 NPC 的常见抱怨——它没看见我、它记错了、它没有自我、它只为我而存在、它与世界无关——用关系语言描述，比用「模型幻觉」「上下文不足」更贴近实际体验。

五个关系条件

「玩家想要的、可相信可改变、会留下后果的他者」可以拆成五条可直接检验的条件：

  • 它看见我反应针对我的当前状态，而不是通用模板。
  • 它记得我记得关系里要紧的事，允许琐事淡去。
  • 它是它自己有边界，会拒绝，不能被任意改写。
  • 它可以被我改变我的行为在它身上留下痕迹，并且改变有代价。
  • 它超出我有自己的作息、关系与行为，不专为我而存在。

五条之间互相拉扯，因此「好智能体」不是某一项指标最高，而是在这些张力之间保持稳定。这也解释了为什么单靠模型升级解决不了「像不像真的」。

二 · 最小关系模型

七个维度收敛为三原语与两施行条件

把玩家侧的描述压到结构层，剩下的只有三件事必须在时间里被计算、被保证，以及两件让它们真正被玩家读到的事。

最小关系模型：三原语与两施行条件
类别条件含义
结构原语连续性 Continuity关系状态在时间上持续存在并累积
结构原语玩家条件性 Contingency行为稳定地、可见地依赖于这位玩家
结构原语独立性 Independence拥有不来自玩家输入的状态与目标
施行条件表达 Expression状态被表现出来，玩家能读到；看不见的状态等于不存在
施行条件互惠 Reciprocity关系是双向的，而非单向服务

「惊喜」被降级为结果而不是原语：随机与幻觉同样能制造惊喜，它无法区分「活」与「死」。「看见我」是索引在身份上的条件性，「记得我」是这种条件性的持续，「我可以改变它」是条件性在时间上的展开。

可证伪

在匹配表层质量的前提下，如果只提升能力——更强模型、更长上下文、RAG 记忆——也能同等幅度地提升玩家感知到的关系，本命题即被推翻。

三 · 缺口在哪里

缺的不是信息量，是一整个场

缺口不在信息量。玩家理解 NPC 时同时站在两个参照系里——游戏内的角色，以及知道系统规则、任务目标与自身经验的玩家；而 NPC 只活在其中一个。它并不「知道得更少」，而是缺少一整层接收与解释信息的场。因此加传感器、扩大感知范围、调高信息权重，都补不上这个缺口。

这也给出了「真实感」的新判据：NPC 显得假，往往不是因为感知数据太少、模型太小或行为树太浅，而是玩家始终在叠加的参照系里解读它，而它只对其中一个负责。任何来自游戏外视角的解读——「这是脚本」「它只有三句台词」「它在等我交任务」——都会直接戳破真实感。

场叠加是这幅图景的第一个切片，不是全貌。它最擅长解释「玩家与 NPC 对同一事件的解读为何不在同一位置」，但单独解释不了 NPC 为什么该记得、为什么该拒绝、如何被改变、如何超出玩家。

四 · 架构落点

一个以玩家为索引的持久关系状态

架构上的结论只有一句：框架应当保证一个以玩家为索引的、持久的、可解释的关系状态——社交层面的存档，而不是只把模型能力做大。为此 Macha 被拆成两个可分离的系统加一个契约：Macha Core 负责认知，环境集成层（Environment Integration Layer）负责把恰好一个外部环境接上，两者之间只有一层协议。

  • 规则一Macha Core 不知道自己在哪个环境里运行。Core 里不得出现任何引擎导入、引擎类型、引擎标识或 tick 语义。
  • 规则二Layer 不思考。它可以翻译、观察、声明与拒绝，但不得记忆、判断、规划或持有任何人格。
  • 规则三Minecraft 是测试用例，不是框架身份。Skyrim、Cyberpunk 2077、Unreal、Unity、仿真与机器人适用同一条规则。
整个架构的可证伪条件

如果接入第二个 Layer 需要修改 Macha Core，那就是协议错了——改协议，而不是改 Core 的身份。

技术模块只是交付这些保证的手段，而不是目标本身。五个关系条件在架构上对应五类保证：被看见的保证、被记住的保证、有边界的保证、可被改变的保证，以及不完全属于玩家的保证。

五 · 主张

我们愿意被引用的一段话

一个 NPC 是否可信，不取决于它有多聪明，而取决于玩家能否在它身上看见一段持续的、属于自己的、且不完全围绕自己的关系。

六 · 当前状态

先做 Layer，后做认知核心

Macha 目前处于仓库初始化与 Layer 协议阶段。按 2026-09-13 的排序决定，先做 Layer、后做认知核心：第一个可验证的里程碑是 Layer 协议 + Stub Core + Minecraft Layer，而不是认知核心。认知核心尚未构建，属于 Phase 3；没有可用的 demo，也没有产品。
